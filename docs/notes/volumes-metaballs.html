metaballs — blobby spheres added into a 16×16×16 grid

A volume in this engine is a named block of 4096 floats (16×16×16, index x + 16y + 256z, blob.c). volume3D creates one (optionally loading v8.dat / vbox.dat, which are just 16 KB of raw floats), clearvolume and copyvolume reset it. metaballs OurVolume test1.mbs reads exactly 8 text lines “X Y Z R C” from the file; every field is an expression of Frame (for example sin(Frame*0.006*3.4+5.4)), evaluated each frame with the same expression compiler as the rest of the script. The field of a ball is added (+=, nothing is cleared) to the volume. Grid point i sits at (i−8)·0.25 on each axis, so the 16 points cover −2 … +1.75.

The falloff is a quartic in the squared distance, f(d²) = (A·d² + B)·d² + C with A = C/R&sup4;, B = −2C/R²: it equals C at the centre and goes to zero with zero slope at d² = R², so no square root is needed and balls blend smoothly. Negative C (the strength column of test1.mbs alternates between +0.5 and −0.9) digs holes into the field. To stay fast on a 486/Pentium the code first builds three tables of 16 squared distances per axis, clips the loops to the box where dx² ≤ R², and only evaluates the polynomial inside the sphere. The blob library also contains a second primitive type (type 2, 0x16dc9) that the script never uses.
