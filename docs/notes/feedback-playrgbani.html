playrgbani - 24 bit animation with frame cross-fade

The 40-frame, 320x180 "nebar" animation (the glowing bars shown at order 5-6) is played into a 32 bit buffer. The playback position is f = seconds * fps (7 frames per second); the picture shown is a cross-fade between frame floor(f) and the following frame, weighted by the fractional part, so the 7 fps animation looks smooth at 30-60 Hz. At the end the position wraps with fmod (loop flag = 1) and the "next" frame of the last one is frame 0.

The blend is done without a single multiplication per pixel: two 256 entry byte tables tabA[i] = trunc(i*(1-frac)) and tabB[i] = trunc(i*frac) are rebuilt each frame and every channel is tabA[a] + tabB[b]. The helper at 0x4f5d8 patches the table addresses into the displacement fields of the loop (self-modifying code again, the tables are indexed with a fixed 0x3e7 offset in the listing before patching), and the loop converts 3-byte packed pixels into 4-byte 0x00RRGGBB pixels.

The 3rd parameter (10) is a y offset: the 180-line animation is centred in the 200-line buffer, rows 0-9 and 190-199 stay untouched. In the web port the original nebar.ani (bzip-like block coder) is read from nebar_sheet.png, an 8x5 sheet of the 40 frames.

Cross-fade loop (0x4f65a)

4f65a  mov al, byte ptr [edi + 0x3e7]; a0 = frame A, byte 0   (24 bit pixels, 3 bytes)
4f660  mov bl, byte ptr [edi + 0x3e8]; a1
4f666  mov cl, byte ptr [edi + 0x3e7]; b0 = frame B, byte 0
4f66c  mov dl, byte ptr [edi + 0x3e8]; b1
4f672  mov al, byte ptr [eax + 0x3e7]; tabA[a0]   (the table address is patched into the displacement by 0x4f5d8)
4f678  mov bl, byte ptr [ebx + 0x3e7]; tabA[a1]
4f67e  mov cl, byte ptr [ecx + 0x3e7]; tabB[b0]
4f684  mov dl, byte ptr [edx + 0x3e7]; tabB[b1]
4f68a  add al, cl; out0 = tabA[a0] + tabB[b0]
4f68c  add bl, dl; out1
4f68e  mov cl, byte ptr [edi + 0x3e9]
4f694  mov dl, byte ptr [edi + 0x3e9]; a2 / b2
4f69a  mov byte ptr [esi + 0x3e7], al; write 3 bytes of a 4 byte pixel
4f6a0  mov byte ptr [esi + 0x3e8], bl
4f6a6  mov cl, byte ptr [ecx + 0x3e7]
4f6ac  mov dl, byte ptr [edx + 0x3e7]
4f6b2  add cl, dl; out2
4f6b4  add esi, 4; next destination pixel (+4)
4f6b7  add edi, 3; next source pixel (+3)
4f6ba  nop
4f6bb  mov byte ptr [esi + 0x3e9], cl; the 4th byte of the pixel is left alone
4f6c1  jne 0x4f65a

Port

let f = f32(f32(f32(fr - t0) / 100) * fps);            // frames elapsed
f = fix(f); let g = fix(f32(1 + f));                     // fix(): loop with fmod(.,last) or clamp
const frac = f32(f - Math.floor(f)), inv = f32(1 - frac);
for (let i = 0; i < 256; i++) { tabA[i] = ftol(i*inv) & 255; tabB[i] = ftol(i*frac) & 255; }
// out = tabA[frame ia] + tabB[frame ib]  per channel, ia = trunc(first+f), ib = trunc(g)
script
playrgbani name {} {SCREEN2} {nebar.ani 320 180 10 0 39 1 7.0} = file, width, height, y offset, first frame, last frame, loop, frames per second (sscanf "%s %d %d %d %d %d %d %f")
buffers

timeline

original
init 0xf96c, run 0xfa5f, free 0xfce9; blend 0x4f601 / table patch 0x4f5d8. The script line loadanim nebar.ani is commented out, the engine finds the animation by name in a global table (0x10b350) anyway
verified
5 consecutive frames of the original: all 64000 pixels identical (including the 3 stray rows below the animation which the original leaves untouched)
