matrix - 3x3 convolution without multiplications (and a bug)

For an 8 bit image (used on SCREEN8 around order 23 for an embossed look) the nine kernel coefficients are turned into nine 256 byte lookup tables T_k[v] = trunc(v*m_k) & 255. The loop then only does table lookups and 8 bit adds, wrapping modulo 256 (negative coefficients work thanks to the wrap); the tenth parameter is a constant added to every pixel (trunc(255*m), 1.0 gives -1). Only interior pixels are written, the border is left untouched.

The centre tap is lost: the code loads dl = [esi] and then executes xor edx, edx before using it as an index, so the centre coefficient (-2.0 in the script) always reads T4[0] = 0. We found this by probing the original with single-coefficient kernels.

; 0x5276a  loop body (esi = centre pixel, edi = -width, ebp = +width)
527a5  mov al, [eax+0x112de8]   ; T0[top-left]     (tables are 256 bytes apart, patched code, no multiply)
527ab  mov cl, [ecx+0x1130e8]   ; T3[left]
527bb  mov bl, [ebx+0x1133e8]   ; T6[bottom-left]
527b7  add al, cl
527c2  add al, bl
527c5  mov dl, [esi]            ; centre pixel ...
527cd  xor edx, edx             ; ... thrown away
527cf  mov dl, [edx+0x1131e8]   ; T4[0]
527d5  mov bl, [ebx+0x112ee8]   ; T1[top]
527db  mov cl, [ecx+0x1134e8]   ; T7[bottom]
...
5280f  mov cl, [0x113938]       ; the constant
52826  mov [esi+0x34083], dl    ; imm32 patched with (out - in): store to the output image

d[p] = (T[s[p-w-1]] + T[256+s[p-w]] + T[512+s[p-w+1]] + T[768+s[p-1]] + T[1024]
