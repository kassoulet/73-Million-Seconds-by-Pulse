Lens-flare particles (setupflares / flareparticles)

Between about 88 s and 106 s a cloud of soft glowing blobs streams along the camera path of smoke.exp. Every one of the five lights of that scene (f2.source ... f2.source04) owns a flareparticles event with 100 particles. A particle is born on the (moving) light, drifts with a random velocity, grows from nothing to 200 and then 300 world units while it fades out, and is finally reborn. Nothing is a polygon: each particle is a screen-aligned square that is texture-mapped with the 128x128 greyscale flare2 picture and added to an 8-bit buffer.

The original is plain Watcom C for the particle logic (float maths, rand()) and a hand-written, self-modifying assembly routine for the blitter at 0x5976c. The routine patches the texture address, the table address and the 16.16 texture steps straight into the inner loop before running it, so the loop needs no spare registers: 8 instructions per pixel. Each texel goes through a 256-entry table row ((texel*intensity)>>8, built once at start-up) and is added to the destination with unsigned saturation (add, sbb dl,dl, or: no branch, no MMX).

The random generator is the Watcom rand() (LCG 0x41C64E6D, 0x3039, bits 16..30) with no srand, so the sprite cloud is the same every run. setupflares only evaluates its expression (here 2) and stores it in the scene record, where the 3D renderer reads it as the size factor of its own light halos; the particles do not use it. ctx.control is not used by these effects.

Inner loop of the sprite blitter (0x59954 - 0x59989)

; ecx = (v<<8)|u  (ch = texture row, cl = texture column, 8 bit wrap)   esi = fraction of u in the top 16 bits
; the immediates marked * are rewritten at 0x597d9..0x59943 before the loop starts
59954  mov cl, [0xc89fe]            ; start column (integer part of u0)
5995a  mov esi, [0xc8a00]           ; fraction of u0 << 16
59960  mov ebp, [0xc8a20]           ; pixels in this row
59966  xor eax, eax
59968  mov al, [ecx + 0x1869f]      ; * texel = texture[ecx]       (imm32 = texture base, patched at 0x5996a)
5996e  add esi, 0xbc614e            ; * u fraction += du_frac<<16    (patched at 0x59970)
59974  adc cl, 0xc                 ; * u int += du_int + carry     (patched at 0x59976)
59977  mov bl, [edi]               ; destination pixel
59979  add bl, [eax + 0x98967f]     ; * += table[intensity*256 + texel]  (patched at 0x5997b)
5997f  inc edi
59980  sbb dl, dl                  ; carry -> 0xff
59983  or  bl, dl                  ; saturate to 255
59985  dec ebp
59986  mov [edi-1], bl
59989  jne 0x59968
; end of row: advance v the same way
5998b  mov ebp, [0xc8a04]  / 59991 mov ebx, [0xc8a28] / 59998 mov edx, [0xc89e0] / 5999e mov al, [0xc89de]
599a3  add ebx, edx                ; v fraction += dv_frac<<16
599a5  adc ch, al                  ; v int += dv_int + carry
599b3  add edi, [0xc8a18]          ; skip to the next screen row

Before the loop the routine turns the four floats (centre, width, height) into a rectangle with the classic magic number trick: fadd 1.5*2^36 then store as a double, whose low 32 bits are the value in 16.16 fixed point (round to nearest even). The left/top edge is rounded up (add 0xffff, sar 16), clipped against the screen, and the texture start is moved by the clipped amount times the step.

5976c  pushal
5976d  fld st(0)  / fmul [0xc89d0] (=0.5)    ; half sizes
...    (x0=X-W/2, x1=X+W/2, y0=Y-H/2, y1=Y+H/2)
597b1  fstp qword [0xc89f4] ...              ; x0,y0,x1,y1 + 1.5*2^36  (fadd [0xc8a14] before)
597cd  fdivr dword [0xc5548]                 ; du = 128 / W   (texture width / sprite width)
597d9  mov [0x5996a], edx                    ; self-modifying code: texture pointer
597df  mov [0x5997b], ebx                    ;                      shading table row
59843  fdivr dword [0xc554c]                 ; dv = 128 / H
598c8  fmul st(1) ... fmul st(3)             ; u0=(x0c-x0)*du, v0=(y0c-y0)*dv  (sub-pixel start)

Particle update (flareparticles run, 0x1ac7e)

1af75  fld  [esi+0x18]  / fadd [dt]  / fstp [esi+0x18]      ; age += dt
1af81  fld  [esi+0x1c]  / fadd [esi+0x20]                   ; fade-in + fade-out time
1af8d  fcomp [esi+0x18] / jae 0x1b09b                       ; still alive -> move
        ; dead: copy the light position, new random velocity (3 x rand()), age = 0
1b09b  fld [esi+0x0c] / fmul [dt] / fadd [esi] / fstp [esi]     ; x += vx*dt   (y, z likewise)
1b0d2  fld [esi+0x18] / fcomp [esi+0x1c] / jbe 0x1b127          ; age > fade-in ?
1b0e0  t=(age-in)/out ; size=(300-200)*t+200 ; intensity=(0.01-0.2)*t+0.2   (fade out)
1b127  t=age/in       ; size=(200-0)*t+0   ; intensity=(0.2-0)*t+0          (fade in)
1b166  fld intensity / fmul 255.0 / call 0x1ed6a (frndint, truncating) / cmp 0xff
1b1c0  view = M * p + T  (3x4 matrix at camera+0x98), then 0x588d8: sx = vx*fx/vz+160, rejects vz <= near
1b25b  half-size = fx*size/vz ; skip if >= 320 ; call 0x5976c(width, texture, table + (idx<<8), W, H, sx, sy)

Script
setupflares naz1 {} {} {scena 2}, then five flareparticles nazN {} {SCREEN8} {scena 0 f2.sourceNN 100 30 370 0.6 0 0 200 300 0 0.2 0.01}; followed by radialblur, blit to SCREEN, blend with TLO. Order 12 row 60 to order 15 row 16 (88.2 s to 106 s).
Parameters
scene event, camera, light, particle count (100), fade-in 30 cs, fade-out 370 cs, velocity range 0.6, life randomness 0, size 0 / 200 / 300, intensity 0 / 0.2 / 0.01.
Buffers
8-bit SCREEN8 (320x200, palette applied later); textures flare1/flare2 = 128x128 8-bit PNG kept with a row stride of 256; table 256x256 bytes.
Data
lights and camera come from smoke.exp (3D Studio style TCB spline tracks, animation speed 69 units/s). Particle record: 9 floats (36 bytes).
