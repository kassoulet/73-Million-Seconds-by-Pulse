The software 3D renderer: z buckets, magic-number fixed point and shadow-volume beams

One frame of a scene (0x4fa0) evaluates the key tracks, then 0x2b21f transforms every vertex into camera space, projects it (0x587f1: x = X*zoom/Z + w/2), sorts the polygons into 1024 depth buckets (a linked list per bucket, drawn from the far bucket to the near one — no z-buffer, a painter's algorithm; the original even prints "RSorting range exceeded" when a bucket index leaves 0..1023) and hands each polygon to one of about 25 handwritten scanline fillers (0x612fc ... 0x74f88) chosen from the target depth (8, 16 or 32 bit), the surface shading mode and its transparency. Only two fillers are used by the demo: the textured, alpha blended filler 0x6f75c for the 32-bit scenes (affine u,v taken from an environment map: the camera-space vertex normal selects the texel, u = 128 + 127.5*n.x, v = 128 + 127.5*n.y on a 256x256 texture such as echo.png), and the beam filler 0x612fc for the 16-bit target of aziz1.lwe.

All fillers convert floats to 16.16 fixed point with the classic magic number trick: adding 1.5*236 ([0xc8c30] = 0x51c00000) to a float leaves the 16.16 fixed-point value in the low dword of the double that is then stored. This only works with the x87 precision control set to 53/64 bits. This is why the first golden frames of the 3D scenes were black: the emulation snapshot restored the CPU registers but not the FPU control word, so Unicorn ran with FPCW=0 (24-bit precision, all exceptions unmasked), the sum was rounded to single precision, the fixed-point value became 0 and every triangle was empty. Setting FPCW = 0x37f after loading the snapshot (re/emucore.py) fixed it.

Beams = shadow volumes accumulated as scanline deltas

For a scene loaded with the flag i and after beamson, the polygons of the object are not drawn. Instead, for every polygon the three side quads of the prism obtained by pushing each vertex away from the first light (v + (v - L) * 9999) are rasterised into a 16-bit buffer with the filler below, which does not store pixels at all: it adds k to the first pixel of every scanline span and subtracts it after the last one. The row prefix sum (the interpolator effect, SCREEN16 -> SCREEN8) turns this into the number of shadow-volume faces covering each pixel, i.e. the radial light shafts of the first scene. Cost per span is two memory operations whatever its length.

; 0x612fc inner loop, span of one scanline (ebx = row base, ecx = x1, edx = x0, ax = k = 2)
616c4  mov  ebx, dword ptr [0xc8c18]       ; row start of this scanline (from the row table at 0x119100)
616ca  sub  ecx, edx                        ; span length
616cc  jbe  0x616e1
616ce  cmp  ecx, 0x3e8                      ; spans longer than 1000 are dropped
616d4  jg   0x616e1
616d6  lea  edi, [ebx + ecx*2]
616d9  add  word ptr [ebx + edx*2], ax      ; +k at the left edge
616dd  sub  word ptr [edi + edx*2], ax      ; -k right after the last pixel
616e1  fadd dword ptr [0xc8c3c]             ; x_left  += dx_left   (both edges are x87 doubles with the magic number)
616e9  fadd dword ptr [0xc8c24]             ; x_right += dx_right
61703  inc  ecx                             ; next scanline
61704  mov  edx, dword ptr [0x11a108]       ; pitch
6170a  add  ebx, edx

// raster.js: triDelta16 - same edge rounding as the original ((x*65536 + 0xfff0) >> 16 == ceil(x - 1/16))
function spanDelta(y, xl, ul, vl, xr) {
  let x0 = q(xl), x1 = q(xr); if (x1 <= x0) return; /* clip to the row */
  const p = y * _W; _dst[p + x0] += _k; if (x1 < _W) _dst[p + x1] -= _k;      // Uint16Array wraps like the original
}

Measured on the original buffer (frame 520 of aziz1): every row sums to exactly zero, the deltas are multiples of 2 (the weight of a prism quad; weight 7 is used for the polygon itself) and the object's shadow shows up as the dark core of the image. The port reproduces the overall structure (dark core, radial wedges) but not pixel for pixel: the original rejects quads with a vertex behind the camera through an outcode flag and re-uses stale screen coordinates, which is not reproducible (mean integrated value 32 in the original, 55 in the port; mean absolute difference 26).

; 0x2b915  prism: vertex + (vertex - light) * 9999, done for all three vertices of the polygon (camera space +0x18,+0x1c,+0x28)
2b91b  fld  dword ptr [eax + 0x18]
2b91e  fsub dword ptr [ebp - 0xe8]          ; - light.x
2b924  fmul qword ptr [0xb9001]             ; * 9999.0
2b92a  mov  eax, dword ptr [ebp - 0xf4]
2b930  fld  dword ptr [eax + 0x18]
2b933  faddp st(1)
2b935  fstp dword ptr [ebp - 0x140]

The 32-bit scenes (aziz2.lwe, vol.lwe, obj1.lwe, the boxes) are drawn with the textured filler. Their transparency is the surface byte +0xa7 (lwotr: 255 = opaque, 57 = 22 %); aziz2 shows the same translucent, environment-mapped bubbles as the original (compared by eye with the golden frame). The 8-bit scene (smoke.exp into SCREEN8) is drawn with the luminance of the texture as palette index (approximation).
